# `results/` — decision records

**Do not reorganise this directory.** Of its 125 files, **0 are unpinned**: 64 are named inside
`prereg/` freeze receipts (several externally timestamped), 9 are hashed evidence in a claim ledger, 11
are cited by other decision records, and the rest by code or documentation. Moving a file here breaks a
registration that cannot be repaired by regenerating the file, because the receipt hashes exact bytes at
an exact path. Run `python scripts/check_pinned_paths.py` after touching anything here.

## Why this is separate from `outputs/`

They are two different tiers and merging them would be actively harmful:

| | `results/` | `outputs/` |
|---|---|---|
| contents | decision records for registered gates | regenerable analysis artifacts |
| lifecycle | append-only; a gate fires once | delete and rebuild freely |
| protection | `results/confirmatory/` is access-gated | none |
| if deleted | registration is destroyed | re-run the guard script |

`src/governance/access.py` names `results/confirmatory` in `PROTECTED_ROOTS` and refuses to open
anything beneath it without a verified unlock receipt. Folding `outputs/` in here would put regenerable
files inside an access-gated evidence tree; folding `results/` into `outputs/` would strip the gate.

## Subdirectories

| Path | What | Protected |
|---|---|---|
| `confirmatory/` | one-shot registered gate outcomes — Baltimore B-G1/B-G2, nature-recovery R-G1, SPB at-berth pollution intensity, labour spatial replication, emissions component validation | **yes** — `assert_confirmatory_unlocked` |
| `development/` | pre-registration development decisions — G1 full-census and 8-day runs, queue-boundary reanalysis, freight boundary, feasibility screens, final gate claim audit | no |
| `deep_case_SPB/` | San Pedro Bay deep-case working results — H1 mass balance, H5 equity baseline, AQ interaction, wind-oriented analysis | no |
| `exploratory/` | protocol scaffold: all exploratory work is written here, never to `confirmatory/`. Kept even when empty — `tests/test_protocol_scaffold.py` asserts it exists | no |

## Rules

- Confirmatory results are written once, by the registered driver, after an unlock receipt is verified.
  Do not re-run a fired gate to "refresh" a file.
- A failed gate stays recorded as failed. Do not delete or soften a negative result.
- A development result may be regenerated by its named driver; a confirmatory one may not.
